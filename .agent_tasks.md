## Current Spec

### 1. Branch Name
`feat/fix-hevc-decoding-baseline`

### 2. Repository Context
The repository is an Android application prototype built using Jetpack Compose, featuring:
- **`NvrService`**: A foreground service that manages background ingestion and motion detection.
- **`StreamIngester`**: Coordinates simulated RTSP ingestion or physical CameraX sensor frames.
- **`DashboardScreen`**: Contains a video player section which currently utilizes `VideoView` to stream/play video clips and feeds.
- **`ClipRecorder`**: Handles recording simulation using `MediaMuxer` and enforces retention.

In the current setup, H.264 streams are supported by default on all devices due to universal hardware AVC support. However, when H.265 (HEVC) encoded streams are fed into the application's playback pipeline, it fails silently, hangs, or crashes on devices/emulators lacking native HEVC hardware decoders. This task focuses on implementing on-device capability checks, robust HEVC decoder selection, failure observability, and a graceful UI fallback state when decoding is unsupported.

### 3. Exact Files/Components to Inspect
- **`DashboardScreen.kt`**: Check the video player initialization inside `AndroidView` (around lines 1060-1090). We need to implement device capability detection before initializing `VideoView` or configure it to catch decoding errors.
- **`NvrService.kt`**: Inspect how video paths are specified. Understand how stream MIME types are configured.
- **`StreamIngester.kt`**: Check if any real-time decoding pipeline exists that handles the incoming streams, and ensure codec verification is logged.

### 4. Change Plan
1. **Decoder Capability Assessment**:
   - In `DashboardScreen.kt`, query the system's `MediaCodecList` using `MediaCodecList(MediaCodecList.REGULAR_CODECS)` to inspect if a decoder exists for `video/hevc` (HEVC/H.265).
   - Log all found H.265 decoders (e.g., `OMX.google.hevc.decoder`, hardware-accelerated vendor decoders, etc.) with their hardware acceleration flags (`isHardwareAccelerated`).
2. **HEVC Fallback & Observability UI**:
   - Create a Composable UI state or modifier inside the video player view.
   - Before attempting to play an HEVC/H.265 stream, verify codec support.
   - If the device **does not** support HEVC decoding, display a high-fidelity, clear user-visible error state overlay in the player card: `"H.265/HEVC Decoding is Not Supported on this Device (API Level / Hardware constraint)"` instead of loading indefinitely or crashing.
   - If playback begins and subsequently encounters a decoding or playback error (e.g., in `setOnErrorListener` of `VideoView`), catch it, log the error details clearly (including the extra error code), and display an explicit failure message `"Playback Error: Failed to Decode H.265 Stream"`.
3. **Smallest Viable Fix for HEVC Playback**:
   - Ensure that for supported devices/emulators (e.g., those with `video/hevc` decoders present), the media player is prepared, buffered, and successfully renders the HEVC stream without blocking the UI or entering infinite retries.
4. **AVC / H.264 Regression Verification**:
   - Ensure the checks specifically target H.265/HEVC streams.
   - Verify that H.264 streams (`video/avc`) bypass the H.265 specific fallback screens and play smoothly as before.

### 5. Constraints
- **Strictly compatibility-focused**: Do not refactor the entire player stack to ExoPlayer or VLC unless strictly necessary. If a player change is required, use the simplest integration.
- **No UI changes** outside the player card error overlay. No tablet/large screen improvements, no new event/AI detection capabilities.
- **No codec expansion** beyond H.265/HEVC.

### 6. Tests and Verification Plan
- **Mock H.265 Stream Playback**:
  - Configure or add a mock camera configuration/event with an H.265 stream (e.g., a test URL containing `.hevc` or `.mkv` or a known HEVC video).
  - Test on a device/emulator supporting HEVC (e.g. Android API 29+ emulators usually have `c2.android.hevc.decoder` or `OMX.google.hevc.decoder` software decoders, and physical devices have hardware decoders) to confirm successful rendering.
  - Test on a device/emulator with HEVC disabled or unsupported (or simulate/mock the unsupported codec check) to verify that the UI shows the fallback error screen instantly.
- **Log Verification**:
  - Verify that Logcat prints the list of H.265 decoders, the selected decoder, and details of any playback failure.
- **H.264 Regression Verification**:
  - Open standard H.264 video paths and ensure they play back successfully.

### 7. Explicit Acceptance Criteria
- A known H.265 stream can be opened and rendered successfully on supported test devices/emulators.
- H.264 playback remains working with no regression.
- Unsupported or failing H.265 cases show a clear user-visible error or fallback state instead of silent failure/hang.
- Decoder selection and failure reasons are logged clearly enough for QA and follow-up debugging.
- The branch includes a minimal compatibility matrix in a `COMPATIBILITY.md` or as a comment in code, listing tested device/API combinations, unsupported behaviors, and known limitations.
- Any app crash, ANR, or infinite retry loop specific to H.265 playback is eliminated.
